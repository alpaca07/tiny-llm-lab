# Step 1 이론 노트 — 문자 단위 GPT

코드(`bigram.py` → `attention_demo.py` → `gpt.py`)를 읽기 전에/읽으면서 보는 노트.

---

## 1. 언어모델이란

**언어모델 = 앞에 나온 토큰들이 주어졌을 때 다음 토큰의 확률분포를 내놓는 함수.**

```
P(다음 토큰 | 앞의 토큰들)
```

문장 전체의 확률은 이 값들의 곱(연쇄법칙)이다.

```
P(h, e, l, l, o) = P(h) · P(e|h) · P(l|h,e) · P(l|h,e,l) · P(o|h,e,l,l)
```

LLM이 하는 일은 결국 이게 전부다. GPT든 Llama든 "다음 토큰 맞히기"를 엄청나게 잘하도록 학습한 모델이다. 글을 쓰는 건 이 분포에서 하나 뽑고(샘플링), 그걸 앞에 붙여서 다시 예측하는 걸 반복하는 것(자기회귀 생성).

---

## 2. 토크나이징

모델은 글자가 아니라 **정수**만 다룬다. 문자열 → 정수 리스트로 바꾸는 규칙이 토크나이저.

- 이번 단계는 **문자 단위**: 데이터에 나온 서로 다른 문자 65개가 곧 vocab(어휘) 크기. `a→39, b→40 ...` 식으로 번호만 붙인다.
- 장점: 구현이 5줄이다. 단점: 같은 문장이 매우 긴 시퀀스가 된다(비효율).
- 실제 LLM은 자주 나오는 문자 조합을 묶는 **서브워드(BPE)** 를 쓴다. → Step 2에서 직접 구현.

---

## 3. 학습 데이터 만들기: x와 y

정답은 **입력을 한 칸 민 것**이다.

```
텍스트:  F i r s t   C i t i z e n
x     :  F i r s t   C i t
y     :  i r s t   C i t i      ← 각 위치의 정답 = 바로 다음 문자
```

- 길이 `block_size`짜리 조각 하나에서 **예측 문제가 block_size개** 동시에 생긴다. (`F`→`i`, `Fi`→`r`, `Fir`→`s` …)
- `batch_size`개 조각을 한 번에 묶어 병렬 계산(GPU 효율). → 텐서 모양 `(B, T)`.
- 학습/검증 데이터는 앞 90% / 뒤 10%로 나눈다. 검증 loss가 train보다 계속 높아지면 **과적합**.

---

## 4. 임베딩과 logits

- `nn.Embedding(V, D)` = 크기 `V×D` 표에서 **번호에 해당하는 행을 꺼내는 룩업**. (원-핫 벡터 × 행렬과 수학적으로 같다.)
- 모델의 최종 출력 **logits**: 각 어휘에 대한 점수(아직 확률 아님, 크기 `V`).
- **softmax**로 확률로 바꾼다: `p_i = exp(z_i) / Σ exp(z_j)` → 전부 양수, 합 = 1.

---

## 5. 손실함수: Cross-Entropy

정답 문자의 확률이 `p`일 때 loss = **−log p**.

- 정답에 확률 1을 주면 0, 확률이 낮을수록 급격히 커진다.
- **기준선**: 아무것도 모르고 65개에 균등하게 찍으면 `−log(1/65) = ln 65 ≈ 4.17`. 이보다 낮아야 뭔가 배운 것.
- 참고: `bigram.py`의 step 0 loss가 4.73으로 4.17보다 높은 건 정상이다. 초기 가중치가 정규분포(N(0,1))로 랜덤이라 logits가 균등하지 않고, 틀린 문자에 자신만만하게 몰려 있기 때문이다. 학습이 이걸 먼저 바로잡는다.
- loss 2.0이면 정답 문자에 평균 `e^-2 ≈ 13.5%` 확률을 주고 있다는 뜻 (대략적인 감).

---

## 6. 바이그램 모델과 한계

바이그램: **직전 문자 1개만 보고** 다음 문자 예측. 모델이 곧 `65×65` 표 하나.

- 파라미터 = 표의 칸들. 표의 `i`번째 행 = "문자 i 다음에 올 문자들의 logits".
- 학습 결과 loss ≈ **2.46**에서 멈춘다. 문자 쌍 통계만으로는 더 못 내려가기 때문.
- 생성 결과가 `Thr toud en:` 식인 이유: 철자 습관(`th`, `ou`)은 배웠지만 **단어/문장 맥락은 못 본다**.
- 해결책 = 더 앞의 토큰들도 활용 → **어텐션**.

---

## 7. 셀프 어텐션 — 핵심

### 7-1. 목표
각 위치가 **자기 자신과 과거 토큰들의 정보를 모아** 다음 토큰 예측에 쓰는 것. 미래 토큰은 정답이므로 **절대 보면 안 된다**(마스킹).

### 7-2. 가장 단순한 형태: 과거 평균
위치 t의 출력 = 0~t번 토큰 벡터의 평균. 세 가지로 계산해도 결과가 같다 (`attention_demo.py`로 확인):

1. for 루프
2. **하삼각 행렬**(`tril`)을 행 합 1로 정규화해서 행렬곱 (`w @ x`)
3. 미래 칸을 `-inf`로 채우고 **softmax** → `-inf`는 확률 0이 되고 나머지는 균등 → 어텐션이 실제로 쓰는 형태

핵심: 이 "가중치 행렬 `w`(T×T)"를 **고정 평균이 아니라 데이터에서 계산**하게 만든 게 셀프 어텐션이다.

### 7-3. Query / Key / Value
각 토큰이 세 가지 벡터를 만든다 (모두 학습되는 선형변환).

| 이름 | 비유 | 역할 |
|------|------|------|
| Query (Q) | "내가 찾는 정보" | 현재 토큰이 던지는 질문 |
| Key (K) | "내가 가진 정보의 라벨" | 다른 토큰이 이 토큰을 찾을 때 비교하는 대상 |
| Value (V) | "내가 실제로 건네줄 내용" | 선택되면 가져가는 정보 |

```
Attention(Q, K, V) = softmax( Q Kᵀ / √d_k  +  마스크 ) · V
```

과정:
1. `Q Kᵀ` : 모든 (질문, 라벨) 쌍의 유사도 점수 → `(T, T)` 행렬
2. `/ √d_k` : 크기 조정 (아래 7-4)
3. 마스크: 미래(오른쪽 위 삼각형)를 `-inf`
4. softmax: 각 행을 확률(합 1)로 → "어느 과거 토큰에 얼마나 주목할지"
5. `· V` : 그 비율대로 Value를 섞어서 출력

### 7-4. 왜 √d_k로 나누나
Q, K의 각 성분이 평균 0 / 분산 1이면 내적 `q·k`의 분산은 **d_k**가 된다 (d_k개를 더하니까). 값이 너무 커지면 softmax가 **거의 one-hot으로 포화**되어 한 토큰에만 몰리고 **기울기도 사라진다**. `√d_k`로 나눠 분산을 1로 되돌린다.

### 7-5. 위치 정보
어텐션은 토큰 **집합**에 대한 연산이라 순서를 모른다 (`ab`와 `ba`를 구분 못 함). 그래서 **위치 임베딩**을 토큰 임베딩에 더해서 "몇 번째 자리인지"를 알려준다. `gpt.py`는 학습되는 위치 임베딩(`nn.Embedding(block_size, D)`)을 쓴다. (Step 4에서 RoPE로 교체)

### 7-6. Multi-Head
헤드 하나는 "한 가지 관점"으로만 주목한다. 헤드를 여러 개 두면 서로 다른 관계(예: 직전 글자, 같은 단어 안의 앞 글자, 따옴표 짝 등)를 **병렬로** 본다.

- 임베딩 차원 `D = 64`, 헤드 4개 → 헤드당 `head_size = 16`.
- 각 헤드 출력을 이어붙이면(concat) 다시 64차원 → `proj`(선형층)로 섞어준다.

### 7-7. 이 구조가 **디코더(causal)** 인 이유
미래를 가리는 마스크가 있어서 "앞에서 뒤로 생성"하는 GPT 계열이다. 마스크를 빼고 양방향으로 보면 BERT 같은 인코더가 된다.

---

## 8. 트랜스포머 블록

한 블록 = **통신(어텐션) + 계산(FFN)**, 각각 잔차 연결과 정규화로 감싼다.

```
x = x + MultiHeadAttention( LayerNorm(x) )
x = x + FeedForward( LayerNorm(x) )
```

- **어텐션 = 토큰끼리 정보 교환(통신)**, **FFN = 각 토큰이 혼자 수행하는 계산(생각)**. 둘이 번갈아 나오는 게 트랜스포머의 리듬.
- **FeedForward**: `D → 4D → D`의 2층 MLP. 4배로 넓혔다 줄이는 게 관례이고, 파라미터의 약 2/3가 여기에 있다.
- **잔차 연결 (`x + ...`)**: 입력을 출력에 그대로 더해서, 기울기가 층을 건너뛰는 고속도로로 흐른다. 층을 깊게 쌓아도 학습이 된다.
- **LayerNorm**: 토큰 벡터 하나의 값들을 평균 0·분산 1로 정규화해 학습을 안정화. 요즘은 블록 **앞**에 두는 pre-norm이 표준 (원논문은 뒤).
- **Dropout**: 학습 중 일부 값을 랜덤으로 끈다. 과적합 방지.

블록을 `n_layer`번 쌓고, 마지막에 `LayerNorm → Linear(D→V)`로 logits를 만든다.

---

## 9. 계산량 감각

- 어텐션 점수 행렬이 `T×T`라서 **시퀀스 길이 T에 대해 제곱**으로 비용이 증가한다. LLM의 컨텍스트 길이가 비싼 이유.
- 현재 설정 `n_embd=64, n_head=4, n_layer=4`의 파라미터는 약 0.2M. GPT-2 small(124M)의 1/600 수준이지만 구조는 똑같다.

---

## 10. 직접 해볼 실험 (이해 점검용)

1. `gpt.py --n_layer 1` / `--n_head 1` 로 줄여서 val loss가 얼마나 나빠지는지 비교
2. `--block_size 8` 로 줄이면? (컨텍스트가 짧을 때 loss 변화)
3. `Head.forward`에서 `/ √d_k` 를 지워보고 학습 초기에 loss 곡선이 어떻게 변하는지
4. 마스킹(`masked_fill`) 줄을 지우면 loss가 비정상적으로 낮아진다 → **왜 미래를 보면 커닝이 되는지** 직접 확인 (생성은 망가진다)
5. `generate(..., temperature=0.5 / 1.5)` 로 샘플링 온도 감 잡기: 낮으면 보수적·반복적, 높으면 다양하지만 엉뚱
