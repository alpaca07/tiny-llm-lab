# Step 4 실습 가이드 — Llama 스타일로 업그레이드

Step 1의 GPT를 현대 LLM 구조로 **한 가지씩** 바꾸고, 바꿀 때마다 성능을 비교한다.

## 원칙
- 한 번에 하나만 바꾼다. 같은 seed, 같은 step 수, 같은 데이터로 loss 비교.
- 결과는 표로 기록한다 (아래 템플릿).

## 교체 항목
| 순서 | 바꾸는 것 | 기존 → 변경 | 핵심 아이디어 |
|------|----------|------------|--------------|
| 1 | 정규화 | LayerNorm → **RMSNorm** | 평균 빼기를 생략해 더 단순·빠르게 |
| 2 | 위치 정보 | 학습형 위치 임베딩 → **RoPE** | Q, K를 위치에 따라 회전시켜 "상대 거리"를 반영 |
| 3 | FFN | ReLU MLP → **SwiGLU** | 게이트(곱 연산)가 있는 FFN. 같은 파라미터 예산이 되도록 은닉 크기 조정 |
| 4 | 어텐션 | MHA → **GQA** | K/V 헤드 수를 줄여 메모리·추론 비용 절감 |
| 5 | 추론 | 매번 전체 재계산 → **KV 캐시** | 지난 토큰의 K, V를 저장해 새 토큰만 계산 |
| 6 | 기타 | bias 제거, 가중치 공유(weight tying) 등 | 선택 |

## 기록 템플릿
| 변경 | 파라미터 수 | val loss | 학습 속도(step/s) | 메모 |
|------|-----------|---------|------------------|------|
| 기준(Step 1 GPT) | | | | |
| + RMSNorm | | | | |
| + RoPE | | | | |
| + SwiGLU | | | | |
| + GQA | | | | |

## 확인할 것
- **RoPE**: 학습 때보다 긴 컨텍스트에서의 동작을 학습형 위치 임베딩과 비교 (학습형은 `block_size`를 넘으면 아예 인덱스 에러)
- **KV 캐시**: 캐시 유무에 따른 생성 속도를 토큰 수를 늘려가며 측정 → 길어질수록 격차가 커지는지
- **GQA**: KV 캐시 메모리가 정확히 몇 배 줄어드는지 계산해서 실측과 비교

## 셀프 체크
1. RoPE가 절대 위치 임베딩보다 길이 확장에 유리한 이유는?
2. KV 캐시는 왜 K, V만 저장하고 Q는 저장하지 않나?
3. GQA는 MHA와 MQA(K/V 헤드 1개) 사이에서 무엇을 절충하나?
