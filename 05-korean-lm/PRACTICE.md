# Step 5 실습 가이드 — 한국어 모델

## 배울 것
- 한국어가 토크나이징에서 왜 불리한지, 그걸 어떻게 완화하는지
- 데이터 준비(수집 → 정제 → 학습용 변환) 과정

## 단계
### A. 코퍼스 준비
- 후보: 한국어 위키백과 덤프, 공개 한국어 말뭉치 등
- **라이선스를 반드시 확인**하고, 출처와 조건을 이 폴더의 `DATA.md`에 기록
- 정제: 중복 제거, 너무 짧은/깨진 문서 제거, 공백·특수문자 정리
- 원본/정제본은 `data/`에 둔다 (gitignore됨, 커밋하지 않는다)

### B. 토크나이저 비교
같은 한국어 텍스트로 아래 세 가지를 비교한다.
1. 바이트 단위 BPE (Step 2에서 만든 것, 영어 위주 학습)
2. **한국어 데이터로 새로 학습한** BPE
3. 문자(음절) 단위

측정: 토큰 수, 압축률(바이트/토큰), 같은 문장이 어떻게 쪼개지는지 눈으로 확인

### C. 학습
- Step 4 구조로 학습, 토크나이저는 B에서 고른 것
- 평가: 검증 loss, 생성 샘플 확인 (조사·어미가 자연스러운지)

## 확인할 것
- 영어 중심 토크나이저는 한글을 바이트 조각으로 쪼개서 **같은 의미에 토큰이 훨씬 많이** 쓴다 → 같은 컨텍스트 길이에 담기는 내용이 적고 비용도 큼
- 한국어 데이터로 vocab을 학습하면 압축률이 얼마나 개선되는지
- 한글은 조합형이라 **음절 단위** 로도 vocab이 꽤 큼 (자주 쓰는 것만 2~3천 자)

## 셀프 체크
1. 같은 문장이 영어와 한국어에서 토큰 수가 다른 이유는?
2. 토큰 수가 많아지면 학습·추론 비용이 어떻게 변하나?
3. 한국어 데이터의 어떤 정제가 결과 품질에 가장 큰 영향을 줄 것 같은가? 실제로 비교해보자.
